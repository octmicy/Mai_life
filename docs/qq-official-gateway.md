# 官方 QQ 网关下的麦生活指令与管理员配置

MaiBot 的 `qq_official_adapter`（QQ 官方机器人平台）拿到的用户标识是 **OpenID**，不是真实 QQ 号。
麦生活的权限链（`admin_user_ids`、用户档案、主人角色）全部按真实 QQ 号匹配——所以官方网关下
**必须先完成 ID 绑定，管理员配置才会生效**。本文是可操作的完整流程。

## 1. 为什么会"管理员失效"

| 层 | 行为 |
| --- | --- |
| QQ 官方平台 | 只下发 OpenID；群聊消息必须 @ 机器人（除非申请全量群消息权限）；客户端输入 `/` 会弹官方指令面板（走 interaction 事件，适配器不处理——**请直接打字发送**，不要走面板） |
| qq_official_adapter | 把 OpenID 当 `user_id` 交给 MaiBot；原始 OpenID 保留在消息路由信息中 |
| 麦生活 | `admin_user_ids` 里是真实 QQ 号 → OpenID 匹配不上 → 管理员指令（`/麦麦立即创作` 等）全部拒绝 |

命令**派发**本身在 v1.25.0 已对齐（子命令 pattern 支持消息任意位置匹配，`@麦麦 /麦麦状态` 中的命令可被派发）。

## 2. 解决：统一 ID 绑定（一次性）

1. 用管理员对应的账号在**单聊**里给机器人发送（推荐单聊，避免群里他人冒绑）：

   ```
   /assign_id 你的真实QQ号
   ```

   群聊里也可以发 `/assign_group_id 真实群号` 把群绑定到真实群号。
2. 绑定立即生效并持久化在适配器的 `id_map.json`：之后所有消息的 `user_id` 都会替换成真实 QQ 号。
3. 此时麦生活的 `admin_user_ids`（或主人用户档案）照旧生效，无需改动。

**安全提醒**：适配器的绑定命令默认**不限制执行人**——群聊里任何成员都可以给自己绑定任意 QQ 号。
建议在适配器配置中把允许执行绑定命令的用户设为已知名单，或只在单聊完成绑定。

## 3. 常见问题

- **输入 `/` 弹出官方指令面板**：那是 QQ 官方平台的指令面板（需要在 QQ 开放平台单独配置），与插件指令无关。直接把命令当普通文本打字发送即可。
- **群里发命令没反应**：确认消息是 `@机器人 命令` 的形态；且该群已绑定（群聊会话按群号归属）。
- **管理员指令仍提示无权限**：检查绑定是否完成（发一条消息看麦生活的互动记录归属）、`admin_user_ids` 是否包含该真实 QQ 号、以及用户档案是否启用（部分指令依赖用户档案）。
