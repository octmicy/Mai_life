# Mai_life v1.11.0 全插件分层重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 对 Mai_life 做分层重构：入口瘦身、服务化、provider 策略、存储查询批量化；重点优化两条线路（搜索服务链、外部网络请求链）与算法热点。对外行为、公开 API、SQLite Schema v9 均保持不变。

**Architecture:** `plugin.py` 只保留入口路由与异常边界；群聊/私聊管线成为独立服务方法。搜索服务抽 `SearchProvider` 策略接口（Playwright 优先、API 备援），健康检查、事件记录、错误分类、冷却去重收敛为共享编排层。天气/地理编码与全部外部 HTTP 统一走 `HttpClient` 一条链。存储新增按 user_id / framework_id 的批量查询接口，消除每用户×契机与每节点一次查询的 N+1。

**Tech Stack:** Python 3.10+、pydantic PluginConfigBase、Playwright Async Chromium、unittest/isolated asyncio、SQLite Schema v9。

## Global Constraints

- 首选语言和所有新增注释/日志/文档文案为简体中文。
- 不修改 MaiBot 主程序、不修改根目录 `.gitignore`、不新增 ConfigUpgradeHook、不新增配置字段。
- `CONFIG_SCHEMA_VERSION` 保持 `1.10.0`，不产生配置迁移；SQLite Schema 保持 v9。
- 不新增/不升级第三方依赖；不使用 `getattr`/`setattr` 掩盖类型错误；错误必须显式分类并记录。
- 每个生产行为先写失败测试，再实现；最终验证命令为全量 `uv run --with pytest pytest -q` 与 `python -m compileall .`。
- 无 WebUI 改动，不运行 `npm run build`；`task_plan.md`/`findings.md`/`progress.md` 维持现状。
